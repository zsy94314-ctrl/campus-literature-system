# 正文写作细纲

本文档用于指导 `final-report-draft.md` 的正式写作。最终报告应严格按照老师《参考目录.docx》的结构组织，重点体现软件工程三级项目要求：可行性研究、需求分析、DFD、数据字典、系统设计、SC 图、接口设计、数据库设计、详细设计、算法伪代码、输入输出设计、界面原型、代码规范、编码实现、测试、维护计划、用户手册、小组分工与自评。

## 最终 Word 排版规范

- A4 打印，左侧装订。
- 不需要页眉，必须有页脚页码。
- 正文字体建议小四号，正文两端对齐。
- 正文段落间距使用最小值 22 磅。
- 目录段落间距使用最小值 14 磅。
- 目录由 Word 自动生成，只保留三级标题，不手动写死页码。
- 每章单独起页。
- 图表必须清晰，图中文字字号适中。
- 图题统一为“图 X-X 名称”，表题统一为“表 X-X 名称”。
- 正文避免大量空白行，图片放不下时应调整图片大小或分页。
- 结论逐条总结完成任务，一般 4 到 5 条。
- 参考文献格式统一，不少于 3 篇。
- 封面成员表以 `docs/team-info.md` 为准。

## 0 封面、摘要与目录

### 封面

写明“软件工程三级项目”、课程设计题目、学校、专业班级、组别、日期、组长和组员信息。每位成员包含学号、姓名、班级和自评成绩百分比。

### 摘要、关键词、Abstract、Keywords

摘要应概括项目背景、技术栈、主要功能、智能检索特点、RAG 风格综述生成流程、离线/在线双模式、课程项目模拟数据边界。关键词建议包含：学术文献检索、多学科语义检索、综述生成、RAG、FAISS、LLM API、Spring Boot。

### 目录

正式 Word 文档中用 Word 自动目录，不手动写页码。目录只保留三级标题。

## 1 引言

### 1.1 项目背景

说明校园学习和课程论文写作中存在文献检索、筛选、收藏、综述整理需求。强调传统关键词检索在跨学科语义理解上不足，直接使用大模型自由生成又存在来源不可控和参考文献编造风险。

### 1.2 项目目标

从普通用户端、管理员端和软件工程实践三方面写。普通用户端关注检索、详情、收藏、推荐、综述生成和记录；管理员端关注文献、分类、用户、统计、索引、LLM 配置；软件工程实践关注 DFD、数据字典、SC 图、接口、数据库、测试、维护、用户手册等完整过程。

### 1.3 参考资料

说明参考软件工程教材、Spring Boot、React、MySQL、FastAPI、FAISS、sentence-transformers、RAG/LLM 工程化资料和 DeepSeek API 官方价格页。不要写真实 API Key、数据库密码或 Token。

## 2 可行性研究

### 2.1 技术可行性

分别分析前端 React + Vite + TypeScript，后端 Spring Boot + MyBatis-Plus + MySQL，智能检索 FastAPI + sentence-transformers + FAISS，在线 LLM OpenAI-compatible API。结论要落到“项目已按这些技术实现并可运行”。

### 2.2 经济可行性

说明主体技术为开源框架，本地运行成本低。DeepSeek API 是可选在线增强成本，不是系统必需成本；离线 `rule` 模式默认可用。可引用 DeepSeek 官方价格页，但不要写真实账户或密钥。

### 2.3 操作可行性

说明普通用户流程符合常见检索系统习惯，管理员后台集中维护数据、索引和 LLM 配置，截图可证明操作路径。

### 2.4 可行性结论

用一段明确结论说明技术、经济、操作和风险控制均可行。

### 2.5 竞品分析

对比知网、万方、高校图书馆检索系统和通用大模型工具。不要声称项目超过真实学术平台；应强调本项目是教学型、可解释、可演示的检索增强式文献系统。

## 3 需求分析

### 3.1 功能需求

使用结构化语言说明输入、处理、输出。普通用户功能包括注册登录、普通检索、高级检索、智能检索、文献详情、收藏、相似推荐、参考文献推荐、离线综述、在线 LLM 综述、综述记录筛选。管理员功能包括文献管理、分类管理、用户管理、数据统计、索引重建、LLM API 管理。

### 3.2 数据流图 DFD

必须插入顶层 DFD、0 层 DFD、智能检索 1 层 DFD、综述生成 1 层 DFD。图后要配文字解释外部实体、处理过程、数据存储和数据流。外部实体包括普通用户、管理员、在线 LLM API；数据存储包括 MySQL 和 FAISS 索引文件。

### 3.3 数据字典

至少写四类表：数据项、数据流、数据存储、数据处理。数据项包括用户编号、用户名、角色、文献编号、标题、摘要、关键词、分类编号、综述编号、generationMode、LLM 配置编号。数据存储包括 `user`、`literature`、`category`、`favorite`、`search_history`、`review_record`、`llm_config` 和 FAISS 索引文件。

### 3.4 非功能需求

写可用性、可靠性、安全性、可维护性和可扩展性。强调 backend-ai 不可用、索引未重建、LLM 不可用时的提示或降级。强调 API Key 脱敏展示和生产环境加密存储建议。

## 4 系统设计（总体设计）

### 4.2 模块结构图（SC 图）

接口设计部分可以配合插入 LLM API 管理流程图和管理员重建智能索引时序图，说明配置管理、active 配置读取、索引重建和跨服务调用顺序。

### 4.4 数据库设计

## 5 详细设计

### 5.1 模块算法设计

详细设计中还应插入面向对象类图和在线 LLM 综述生成时序图，说明实体对象、业务服务和外部 LLM API 的协作关系。
