# AI 辅助交互记录

## 1 使用说明

本项目在开发过程中使用 AI 工具辅助完成需求分析、技术路线讨论、代码生成建议、错误排查、测试用例设计和文档整理。AI 生成的内容经过小组成员的人工检查、修改、本地运行验证和整合后，才纳入最终项目。

需要强调以下几点：

- **AI 是辅助工具**，不替代小组成员的设计判断、架构决策和最终验收。
- 所有核心功能均经过本地编译、运行和页面测试验证，以实际运行效果为准。
- 涉及 API Key、数据库密码等敏感信息未写入 AI 对话或任何项目文档。
- AI 生成的代码和文档均经过人工审核，与项目实际结构一致后才提交。

- 辅助讨论离线规则综述生成与在线 LLM 增强生成双模式的必要性和实现路径。

**示例交互摘要**：
AI 建议将系统拆分为 `frontend`、`backend-java`、`backend-ai` 和 `database` 四个模块：Spring Boot 负责业务逻辑与权限控制，FastAPI 负责语义向量检索，MySQL 存储结构化数据，React 前端负责用户交互。该方案经小组讨论后采纳。

- 辅助设计在线 LLM 增强综述生成逻辑：构造结构化 prompt、调用 Chat Completions API、内容校验。
- 辅助设计 LLM 失败自动降级机制：超时、HTTP 错误、输出截断、参考文献缺失时自动降级为离线规则生成。
- 辅助修复参考文献不完整、LLM 输出截断、`generationMode` 记录与显示等问题。

**示例交互摘要**：

### 3.7 测试与问题修复阶段

以下为 AI 辅助定位并修复的典型问题：

**问题 1：首页分类统计为 0**
- 原因：早期实现仅取前 100 条文献统计，且未区分一级分类与二级分类。
- 修复：后端新增分类统计专用接口，按全部文献和二级分类进行聚合统计。

**问题 2：首页分类跳转检索页不生效**
- 原因：点击分类卡片时传递分类名称字符串，但搜索页需要 `categoryId` 进行精确筛选。
- 修复：点击分类卡片时改为传递 `categoryId`，搜索页通过 URL 参数监听并自动触发分类筛选。

**问题 3：智能检索结果跨学科跑偏**
- 原因：纯向量召回对"人工智能"等泛化词过度敏感，导致查询医学、农业等主题时返回大量计算机类文献。
- 修复：backend-ai 增加多学科主题画像、Query Expansion、MySQL 关键词补充召回和 `finalScore` 重排序。

**问题 4：综述生成模板化**
- 原因：早期综述生成直接拼接文献摘要，内容堆砌、缺乏综合归纳。
- 修复：后端实现主题识别、关键词提取、研究方向自动归纳，基于规则模板生成六个结构化部分的综述。

**问题 5：在线 LLM 生成耗时较长**
- 原因：prompt 塞入完整文献正文导致请求体过大，且前端 axios 默认 timeout 仅 15 秒。
- 修复：压缩 prompt（摘要≤300/200 字、正文节选≤400/300 字），后端 RestTemplate 按配置 timeout 生效，前端放宽至 240 秒，并优化 loading 文案。

**问题 6：LLM 参考文献不完整**
- 原因：模型输出因 `max_tokens` 限制被截断，经常漏写"六、参考文献来源"。
- 修复：后端增加 `ensureReferencesComplete` 方法，根据输入文献强制补全或替换第六节为标准参考文献列表。

**问题 7：LLM 缺少第六节被误判为截断**
- 原因：`isTruncatedEnding()` 在 `ensureReferencesComplete()` 之前执行，且内部检查缺少参考文献时直接抛异常降级，补全逻辑从未被执行。
- 修复：将截断检查与参考文献补全分离。`isTruncatedEnding()` 仅检查最后一行是否以截断词结尾；前五个正文章节完整即可进入后端补全流程。

**问题 8：LLM 输出存在不存在的引用编号**
- 原因：大模型可能产生 `[4]` 或 `[99]` 等超出输入范围的幻觉引用。
- 修复：后端增加 `cleanInvalidCitations()`，正则匹配 `[数字]`，删除所有 `<1` 或 `>N` 的非法引用。

## 4 典型 Prompt 记录

以下仅为交互主题摘要，未粘贴原始聊天全文。

### Prompt 1：智能检索服务设计

**用户需求摘要**：
基于 FastAPI + sentence-transformers + FAISS 搭建 `backend-ai`，支持健康检查、索引重建、语义检索和相似文献推荐。

**AI 辅助结果**：
生成 `backend-ai` 服务设计方案，明确四个接口、向量模型选型（`paraphrase-multilingual-MiniLM-L12-v2`）、向量化字段（标题+分类+类型+关键词+摘要+正文节选）、FAISS 索引文件存储位置和数据流。

---

### Prompt 2：Spring Boot 接入 backend-ai

**用户需求摘要**：
在 `backend-java` 中新增 `/api/ai` 接口，由 Spring Boot 从 MySQL 查询文献并调用 `backend-ai` 完成智能检索。

**AI 辅助结果**：
生成 `AiController`、`AiService`、`AiSearchResultVO`、`SemanticSearchVO` 的实现思路，并说明异常处理（backend-ai 未启动时返回友好错误）和权限控制（普通用户可访问）。

---

### Prompt 3：智能检索结果优化

**用户需求摘要**：
智能检索推荐结果不准确，查询医学主题时返回大量计算机类文献，需要解决跨学科场景下语义泛化问题。

**AI 辅助结果**：
提出多学科主题画像、Query Expansion、MySQL 关键词补充召回、`finalScore` 综合排序和 `weakPenalty` 弱相关降权方案，使检索结果更贴合查询主题。

---

### Prompt 4：综述生成升级

**用户需求摘要**：
综述生成太模板化，内容像摘要拼接，需要从摘要拼接升级为综合归纳型综述。

**AI 辅助结果**：
提出主题识别、关键词提取、研究方向分配、主题化问题与趋势生成方案，使综述具备"研究背景→现状→方向→问题→趋势→参考文献"的完整结构。

---

### Prompt 5：LLM 增强综述生成

**用户需求摘要**：
用户端需要支持离线综述生成和在线 LLM 综述生成，管理员端需要 LLM API 管理功能。

**AI 辅助结果**：
提出 `llm_config` 表设计、管理员配置页面（含脱敏、active 切换、测试连接）、在线生成调用链路、自动降级机制和 `generation_mode` 记录方案。

---

### Prompt 6：LLM 输出不完整修复

**用户需求摘要**：
在线 LLM 综述生成时，参考文献没有写全，或正文在"五、发展趋势"处被截断，缺少"六、参考文献来源"。

**AI 辅助结果**：
提出 `max_tokens` 调整（2500→3000）、`finish_reason` 检查与重试、章节完整性校验、参考文献后端补全（`ensureReferencesComplete`）和非法引用编号清理方案。

## 5 AI 参与边界说明

- AI 可用于**提出方案、生成初稿、辅助排错和整理文档**，但不可直接替代小组成员的架构设计、业务判断和最终验收。
- AI 生成的代码和文档**必须经过人工审核**，确认与项目实际结构一致、无安全漏洞、无幻觉内容。
- 项目功能是否通过，以**本地编译构建、服务启动、页面交互和接口返回**为准，不以 AI 生成内容的"看起来正确"为准。
- 涉及数据库脚本、后端接口、前端页面和 LLM API 调用的修改均经过人工运行验证后提交。
- **API Key、数据库密码等敏感信息不应写入 AI 对话、代码仓库或文档**。

## 7 风险与改进

- **AI 生成内容可能存在错误**：代码可能包含幻觉 API、文档可能遗漏实际字段。本项目通过人工审核和本地运行验证降低该风险。
- **LLM 在线生成存在不稳定性**：响应时间长、输出内容波动、存在网络依赖和费用成本。本项目通过离线规则生成兜底、参考文献后端补全、超时重试和自动降级机制降低该风险。
- **向量检索存在学科泛化偏差**：通用词可能跨学科污染检索结果。本项目通过主题画像、查询扩展、分类过滤和关键词补充召回降低该风险。
- **后续可改进方向**：
  - 增加 API Key 加密存储（AES + 环境变量）。
  - 增加流式输出（SSE）以改善在线 LLM 生成的用户体验。
  - 增加更严格的引用校验和参考文献自动格式化。
  - 增加操作日志审计和异常告警机制。

## 8 小结

本项目合理使用 AI 工具辅助完成系统设计、编码调试、测试分析和文档整理。在开发过程中，AI 主要承担"辅助参谋"和"初稿生成"的角色，最终系统功能、代码整合、运行测试和结果验收由小组成员完成。通过 AI 辅助，项目提高了开发效率，缩短了问题定位时间，但仍坚持人工审核和可运行验证，保证课程设计成果的真实性和可靠性。
