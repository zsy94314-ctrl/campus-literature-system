# 系统测试用例文档

## 1 测试概述

本测试文档用于验证《校园学术文献智能检索与综述生成系统》的主要功能、接口联通性、权限控制、智能检索效果、综述生成效果和异常处理能力。测试覆盖用户端功能、管理员后台、智能检索服务（backend-ai）、LLM API 集成及异常降级机制。

---

## 2 测试环境

| 项目 | 说明 |
|------|------|
| 操作系统 | Windows 10 / 11 |
| 数据库 | MySQL 8.0 |
| 前端 | React + Vite，开发服务器端口 5173 |
| 后端主服务 | Spring Boot 3.2，端口 8080 |
| 智能检索服务 | FastAPI（backend-ai），端口 8000 |
| 浏览器 | Chrome / Edge 最新版 |
| 测试工具 | 浏览器、curl、PowerShell、Maven、npm |
| LLM API | DeepSeek / OpenAI-compatible API（管理员后台配置） |

---

## 3 测试方法

- **页面手动测试**：通过浏览器操作前端页面，验证 UI 交互、数据展示和业务流程。
- **接口测试**：使用浏览器 DevTools Network 或 curl/Postman 验证后端接口返回。
- **编译构建测试**：验证 backend-ai、backend-java、frontend 三个模块能否正常编译构建。
- **权限测试**：验证未登录、普通用户、管理员三种角色的接口访问控制。
- **异常场景测试**：模拟 backend-ai 未启动、LLM API 不可用、索引未重建等异常情况。
- **多学科智能检索结果验证**：使用不同学科主题查询，验证语义检索结果的相关性。
- **综述生成质量验证**：检查生成内容是否包含六个部分、参考文献是否完整、是否存在虚构引用。

## 17 缺陷记录与修复说明

以下为本项目开发过程中发现并已修复的典型问题：

### 1. 首页分类统计为 0
- **原因**：早期实现仅取前 100 条文献进行统计，且未区分一级分类与二级分类，导致大部分二级分类统计数量为 0。
- **修复**：后端新增分类统计专用接口，按全部文献和二级分类进行聚合统计，前端按两级结构展示。

### 2. 首页分类跳转搜索页不生效
- **原因**：点击分类卡片时传递的是分类名称字符串，但搜索页路由和接口需要 `categoryId` 进行精确筛选。
- **修复**：点击分类卡片时改为传递 `categoryId`，搜索页通过 URL 参数监听并自动触发分类筛选。

### 3. 智能检索跨学科跑偏
- **原因**：纯向量召回容易过度识别"人工智能"等泛化词，导致查询医学、农业、法律等主题时返回大量计算机类文献，缺乏学科边界控制。
- **修复**：backend-ai 增加多学科主题画像、Query Expansion、MySQL 补充召回（按学科分类过滤）和 finalScore 重排序，提升跨学科查询的相关性。

### 4. 综述生成模板化
- **原因**：早期综述生成直接拼接文献摘要，导致内容堆砌、缺乏综合归纳。
- **修复**：后端实现主题识别、关键词提取、研究方向自动归纳，并基于规则模板生成包含六个结构化部分的综述。

### 5. 在线 LLM 生成耗时较长
- **原因**：prompt 中塞入完整文献正文，请求体过大，且前端 axios timeout 仅 15 秒。
- **修复**：压缩 prompt（摘要≤300/200 字、正文节选≤400/300 字），后端 RestTemplate 按配置 timeout 生效，前端 review generate 接口 timeout 放宽至 240 秒，并优化 loading 文案。

### 6. LLM 参考文献不完整
- **原因**：模型输出因 max_tokens 限制被截断，经常漏写"六、参考文献来源"或只列出部分文献。
- **修复**：后端增加 `ensureReferencesComplete` 方法，根据输入文献强制补全或替换第六节为标准参考文献列表，确保 `[1]` 到 `[N]` 全部存在。

### 7. LLM 缺少第六节被误判为截断
- **原因**：`isTruncatedEnding()` 在 `ensureReferencesComplete()` 之前执行，且内部检查 `content.lastIndexOf("六、参考文献来源") == -1` 时直接返回 true 并抛异常降级，导致补全逻辑从未被执行。
- **修复**：将截断检查与参考文献补全分离。`isTruncatedEnding()` 仅检查最后一行是否以截断词结尾；前五个正文章节完整即可进入后端补全流程；补全后再做最终校验。

### 8. LLM 输出存在不存在的引用编号
- **原因**：大模型可能 hallucinate 出 `[4]` 或 `[99]` 等超出输入范围的引用。
- **修复**：后端增加 `cleanInvalidCitations()`，使用正则匹配 `[数字]`，删除所有 `<1` 或 `>N` 的非法引用。

## 18 测试结论

经过功能测试、接口测试、权限测试、多学科智能检索测试、综述生成测试和异常处理测试，系统主要功能均能正常运行：

1. **文献管理**：普通检索、高级检索、分类筛选、详情查看、收藏等功能运行稳定。
2. **智能检索**：backend-ai 语义检索能够在多学科场景下返回较相关的文献，Query Expansion 与 MySQL 补充召回有效缓解了跨学科跑偏问题。
3. **综述生成**：离线规则生成内容结构完整，包含六个部分；在线 LLM 生成语言表达更自然；在线 LLM 不可用时系统能够自动降级，保证用户仍可获得综述结果。
4. **权限控制**：未登录、普通用户、管理员三类角色的接口访问控制正确，敏感信息（API Key）脱敏处理到位。
5. **异常处理**：backend-ai 未启动、索引缺失、LLM 超时/截断等异常场景均有友好的降级提示或自动恢复机制。

系统满足课程项目《校园学术文献智能检索与综述生成系统》的设计目标，测试通过。
